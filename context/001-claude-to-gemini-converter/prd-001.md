# PRD: Claude Code to Gemini CLI Command Converter

## Introduction/Overview

This feature creates a TypeScript CLI package that converts all existing Claude Code @commands to equivalent Gemini CLI custom slash commands. The converter will parse Claude Code's markdown-based command files and generate corresponding TOML files that work with the Gemini CLI's custom command system.

The goal is to enable users who are familiar with Claude Code commands to use similar workflows in the Gemini CLI environment, reducing friction when switching between AI coding assistants.

## Goals

1. **Complete Conversion**: Convert all 19 existing Claude Code commands to Gemini CLI format
2. **Functional Equivalence**: Preserve core functionality and intent of each command
3. **Easy Installation**: Provide npm-installable CLI tool for seamless conversion
4. **Zero Configuration**: Work out-of-the-box with standard Claude Code project structure
5. **Valid Output**: Generate syntactically correct TOML files that work with Gemini CLI

## User Stories

1. **As a developer familiar with Claude Code**, I want to convert my existing commands to Gemini format so that I can use similar workflows in Gemini CLI without manually rewriting each command.

2. **As a team lead**, I want to provide my team with converted Gemini commands so that developers can choose their preferred AI assistant while maintaining consistent development workflows.

3. **As a CLI user**, I want to run a simple command that automatically discovers and converts all Claude Code commands in my project so that I don't have to specify input/output paths manually.

## Functional Requirements

### Core Conversion Logic
1. **R1**: The system must parse Claude Code markdown files with YAML frontmatter to extract command metadata and prompt content
2. **R2**: The system must convert argument placeholders from Claude format (`$1`, `$2`) to Gemini format (`{{args}}`)
3. **R3**: The system must generate valid TOML files with `description` and `prompt` fields
4. **R4**: The system must preserve command descriptions from Claude Code frontmatter
5. **R5**: The system must handle file creation instructions by converting Claude's `/context/` patterns to descriptive text in the prompt

### CLI Interface
6. **R6**: The system must provide a CLI command `claude-to-gemini convert` that processes all commands in the `/commands` directory
7. **R7**: The system must create a `.gemini/commands/` directory structure in the project root
8. **R8**: The system must output conversion status and summary (e.g., "Converted 19 commands successfully")

### Package Structure
9. **R9**: The system must be packaged as an npm-installable CLI tool with global installation support
10. **R10**: The system must be written in TypeScript with proper type definitions
11. **R11**: The system must include basic TOML syntax validation for generated files

### Output Quality
12. **R12**: The system must generate filenames that match Claude command names (e.g., `explore.md` → `explore.toml`)
13. **R13**: The system must combine multiple arguments into a single `{{args}}` placeholder where applicable
14. **R14**: The system must maintain readability of converted prompts while adapting format differences

## Non-Goals (Out of Scope)

1. **Tool Restriction Support**: Will not attempt to replicate Claude Code's `allowed-tools` functionality (Gemini CLI doesn't support tool restrictions)
2. **Backward Compatibility**: Will not maintain ability to run converted commands in Claude Code
3. **Command Testing**: Will not automatically test converted commands with Gemini CLI
4. **Custom Command Creation**: Will not provide functionality to create new commands from scratch
5. **Configuration Management**: Will not provide settings or config files for customizing conversion behavior
6. **Incremental Updates**: Will not track changes or support partial re-conversion of modified commands

## Technical Considerations

### Dependencies
- **TOML Processing**: Use `@iarna/toml` or similar for TOML generation
- **YAML Processing**: Use `js-yaml` for parsing Claude Code frontmatter
- **CLI Framework**: Use `commander.js` or `yargs` for command-line interface
- **File System**: Node.js built-in `fs/promises` for file operations

### File Structure
The converter should be placed in `/utils/claude-to-gemini-converter/` as a standalone npm package with its own `package.json`, allowing independent versioning and distribution.

### Error Handling
- Gracefully handle missing `/commands` directory
- Skip invalid markdown files with helpful warnings
- Continue processing other files if individual conversion fails
- Provide clear error messages for permission or file system issues

## Success Metrics

1. **Conversion Accuracy**: All 19 commands convert without syntax errors
2. **Functional Validation**: Converted TOML files parse correctly with TOML validators
3. **User Adoption**: Successful installation and execution on different development environments
4. **Output Quality**: Generated Gemini commands maintain semantic equivalence to original Claude commands

## Open Questions

1. Should the converter handle subdirectory organization for command namespacing?
2. How should commands with complex multi-line output instructions be formatted in TOML?
3. Should there be a dry-run mode to preview conversions before writing files?
